# Pooling and blending by SLP: Haverly's problems

samaya solves models with bilinear rows (pool quality times flow) by successive linear
programming (`docs/SLP_PLAN.md`), the method refinery planning tools use ("distributive
recursion"). Measured on 13 October 2026, build a464cd6, Windows release (MSVC), every answer
checked by the independent verifiers `verify_primal` and `verify_qcp_kkt` on the original model.

## What the status means

Pooling models are nonconvex: they can have several locally optimal plans. SLP finds a
**feasible point where the first-order (KKT) conditions hold** from its starting point, and
samaya reports exactly that, as `first_order_stationary`, never as "optimal". Global optimality
is not claimed, and neither is local optimality (the KKT conditions do not certify it). The row
duals reported are the local marginal values at that point.

## Haverly 1–3 (p-formulation, 7 columns, 6 rows, 4 bilinear terms)

The instances are `tests/instances/haverly{1,2,3}.mps` (QCMATRIX sections, generated by
`cases/pooling.py --haverly`). Published global optima: -400, -600, -750 (cost minimization).

| Instance | Start | Status | Objective | SLP iterations | Verified |
|---|---|---|---|---|---|
| Haverly 1 | near a global solution | first-order stationary | -400 (global) | 4 | yes |
| Haverly 1 | the trap start (49, 0, 49, 0, 49, 0, 3) | first-order stationary | -100 (local) | – | yes |
| Haverly 1 | default (no start given) | first-order stationary | -400 (global) | 8 | yes |
| Haverly 2 | near a global solution | first-order stationary | -600 (global) | 4 | yes |
| Haverly 2 | the trap start (0, 99, 0, 99, 0, 99, 1) | first-order stationary | -400 (local) | – | yes |
| Haverly 2 | default | first-order stationary | -400 (local) | 8 | yes |
| Haverly 3 | near a global solution | first-order stationary | -750 (global) | 3 | yes |
| Haverly 3 | the trap start (74.25, 24.75, 99, 0, 0, 0, 2.5) | first-order stationary | -125 (local) | – | yes |
| Haverly 3 | default | first-order stationary | -750 (global) | 12 | yes |

- From the trap starts the answer is the stationary local point that the plan's reviewer derived
  analytically (and `tests/pooling_check.py` checks independently): SLP is a local method, and
  the report says so.
- The default start reaches the global optimum on Haverly 1 and 3 and a local one on Haverly 2.
  Planners usually start from the previous plan, which is what `--mip-start` takes.

## What the testing changed

Three things were found by running Haverly from the default start (details in
`docs/SLP_PLAN.md` 5a): a start with every flow at zero is a useless KKT point (the empty-pool
trap); the trust region must scale with the flows as they grow; and a second-order correction
is needed, without which Haverly 3 stalled at -718 of -750 after 200 iterations. An independent
review (Codex, astra) of the SLP commit then found two ways to a falsely verified answer
(arithmetic overflow, an unbounded verdict without a feasible point) and three robustness
failures; all are fixed and are regression tests now (a464cd6).
